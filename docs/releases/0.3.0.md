# cpktmisc 0.3.0

This minor release removes bundled LZO and its standalone C89 facade. LZO 2.10
was distributed under GPL-2.0-or-later; it is no longer part of the misc SDK or
libarchive's linked codec closure. It also upgrades the exact core build
prerequisite to cpkt 0.6.1 for all seven targets.

## Compression support

Libarchive continues to read and write gzip using the independently installed
core SDK's zlib, without an external gzip executable. Its bundled bzip2,
xz/liblzma, LZ4 and zstd backends remain enabled. No replacement dependency is
needed.

The complete libarchive public API remains available, including its LZOP entry
points. With the LZO backend disabled, those operations use upstream's external
`lzop` fallback; no `lzop` executable is shipped. Gzip is a different format and
does not decode existing LZO/LZOP-compressed data.

## Consumer changes

The native LZO headers and libraries, `cpkt/lzo.h`, `CpktLzo`,
`CpktLzoFacade`, the `cpkt::lzo` facade targets, and the `lzo2` and `cpkt-lzo`
pkg-config packages are removed. Applications using them must choose another
codec or supply their own LZO dependency under suitable licensing terms.

The retained C89 facade headers and shared-library ABI majors are unchanged.
The core build pin and consumer baseline are cpkt 0.6.1. Core 0.6.1 retains its
compatibility floor of 0.2.0. Core and misc use separate prefixes and ordinary
CMake/pkg-config discovery, with compatibility and payload validation as
described in the README. The core update includes a libssh2 AES-GCM handshake
leak fix; static applications must relink to incorporate updated core code.

## Artifacts

The release contains seven SDK tarballs, the Darwin smoke ZIP, the source tarball
and `cpktmisc-0.3.0-CHECKSUMS`. Darwin build, link and artifact verification uses
local osxcross; native Darwin execution remains a separate diagnostic. Executing
the Darwin smoke bundle requires compatible core libraries on the runtime search
path. Third-party license texts and notices accompany the SDK.
