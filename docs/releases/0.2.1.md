# cpktmisc 0.2.1

This patch release reduces SDK discovery cost and updates the pinned core SDK
to cpkt 0.5.1 for all seven targets.

## SDK validation

CMake reads payload fields from individual JSON entries and queries regular-file
permissions in one host `stat` invocation. Manifest identity, file hashes,
permissions, path safety and symlink checks remain required. Each independent
CMake process validates its selected SDKs; repeated discovery within a process
reuses successful validation.

## Core selection

The exact build prerequisite is cpkt 0.5.1. New misc SDKs record it separately in
`core_build_pin` and use 0.5.1 as their consumer baseline in `requires_core`.
The selected core must match the target and satisfy
`CpktCore_COMPATIBLE_SINCE <= 0.5.1 <= CpktCore_VERSION`.

Core and misc retain separate installation prefixes and ordinary CMake and
pkg-config discovery. pkg-config users must run the installed CMake validator
before linking; the shipped example launchers do this automatically. cpkt 0.5.1
also contains the core-side validation optimization and retains its compatibility
floor of 0.2.0. The unchanged misc 0.2.0 SDK remains usable with that core.

Public C interfaces, shared-library ABI majors and the manifest schema are
unchanged. Misc component versions and facade scopes remain those of 0.2.0.

## Artifacts

The release contains seven SDK tarballs, the Darwin smoke ZIP, the source tarball
and `cpktmisc-0.2.1-CHECKSUMS`. Darwin build, link and artifact verification uses
local osxcross; native Darwin execution remains a separate diagnostic. Executing
the Darwin smoke bundle requires compatible core libraries on the runtime search
path.
