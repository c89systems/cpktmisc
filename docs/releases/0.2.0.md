# cpktmisc 0.2.0

This release allows installed consumers to select an independently upgraded,
compatible core SDK. Builds use the exact published cpkt 0.3.0 pin for each
target. Core and misc remain separate installations; cpktdb is not required.

## Core compatibility and discovery

The consumer baseline is 0.3.0. A selected core must satisfy
`CpktCore_COMPATIBLE_SINCE <= 0.3.0 <= CpktCore_VERSION` and match the misc target.
Both SDKs retain independent payload-integrity validation. A compatible newer
core does not require rebuilding misc. Static applications relink to incorporate
updated core code; shared deployments select the updated core libraries at runtime.

Use ordinary CMake discovery through `CMAKE_PREFIX_PATH` with both prefixes.
Misc packages request the core baseline through `find_dependency`; an application
may additionally request an explicit core version range. For cross builds, add
both prefixes to `CMAKE_FIND_ROOT_PATH` and retain package discovery mode `ONLY`.

pkg-config modules declare `cpkt-core >= 0.3.0`. Version comparisons alone cannot
validate the compatibility floor or SDK payload. Before linking, configure the
installed `lib/cmake/CpktMisc/pkg-config` project in a fresh build directory with
`CPKT_SDK_PREFIX` pointing to misc and the same pkg-config executable and
environment as the link query. The shipped `build-pkg-config.sh` examples perform
this check before invoking the compiler and reject mismatched CMake/pkg-config
core selections.

## Manifest change

Scripts reading SDK manifests must distinguish producer provenance from consumer
requirements:

- `core_build_pin` records the exact build core's `package_id`, `release_version`
  and `target_id`.
- `requires_core` records the consumer baseline as `release_version` and the
  required `target_id`; it no longer contains `package_id`.

The Darwin smoke ZIP records both objects in its package metadata. The manifest
schema marker remains 1. This is a change to the pre-1.0 metadata contract;
consumers that read the previous exact identity from `requires_core` must update
their field selection.

## Interfaces and documentation

Public C interfaces and shared-library ABI majors are unchanged. The misc
dependency pins and supported facade scopes remain those delivered in 0.1.0.
The core upgrade preserves the prior core public headers, exported symbol
surfaces and ABI identities.

Header comments and installed guides clarify audio encoder close/destroy
ownership, transcriber/model and borrowed-string lifetimes, libffi call-plan
ownership, and model-cache selection. The default model directory remains
`${XDG_CACHE_HOME:-$HOME/.cache}/cpkt/susurro/models`; an explicit cache directory
overrides it. Missing or invalid cache entries may be downloaded or replaced
unless offline mode is selected. Source generators preserve these comments.

## Artifacts

The release contains seven SDK tarballs: x86_64, aarch64 and armhf Linux with
GNU and musl, plus arm64 Darwin. It also contains the Darwin smoke ZIP and source
tarball. `cpktmisc-0.2.0-CHECKSUMS` lists every payload and ships alongside them.
Darwin smoke execution requires compatible core libraries on the runtime search
path. Local osxcross verifies the Darwin build, link and artifact contracts;
native Darwin execution remains a separate diagnostic.
